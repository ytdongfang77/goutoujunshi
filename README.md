# 狗头军师 · 组织局增强版

**简体中文** | [English](README_EN.md)

> 先看清局面，再选对聊天方向：从情绪支持、聊天复盘到一句能自然说出口的回复。

[![GitHub Stars](https://img.shields.io/github/stars/ytdongfang77/goutoujunshi?style=social)](https://github.com/ytdongfang77/goutoujunshi/stargazers)

这是由 **ytdongfang77** 维护的狗头军师 Skill，在原项目的关系分析、情绪支持、聊天记录解读与可撤销记忆基础上，加入「组织局」的聊天方向、投入平衡、自然表达与案例复盘方法。

你可以把一句话、几张聊天截图或一段关系经历交给它。它会先分清原话、猜测和未知，判断你现在更适合接话、深入了解、表达欣赏、邀约、修复还是退出，再给出具体可执行的回复和后续分支。需要立即回复时，先给成品；需要完整复盘时，再解释方向与依据。

**它是一套供 AI 助手加载的 Skill，不是独立聊天 App。** 核心能力由支持 Skill 的助手阅读 Markdown 后执行；Python 脚本用于结构检查、资料校验和可选本地记忆，不直接生成恋爱回复。

## 这次加入了什么

- **OFDSP 复盘**：Observe 观察 → Follow 跟进 → Deepen 深入 → Share 自我表达 → Progress 推进；每一步随对方的真实反馈调整。
- **聊天方向判断**：从不停找话题，转向判断当前值得承接的细节、共同兴趣与相处意愿；分别看聊天窗口和进一步发展关系的意愿。
- **投入平衡**：综合主动开启、信息分享、情绪回应与安排兑现，识别一方持续撑场；不把回复速度和字数机械地换算成好感分。
- **自然短句表达**：每条消息只做一个主要动作，保留用户自己的口吻与真实经历；需要时给稳健、轻松或明确边界的版本。
- **8 份原始资料接入**：包括聊天分析模板、方法笔记、表达流程与大型案例手册；通过统一入口按需查阅。
- **可复现验证**：提供文件哈希清单、资料完整性检查及隔离的记忆功能测试，便于确认文件确实上传且辅助脚本可运行。

## 它能帮你解决什么

| 你遇到的问题 | 狗头军师会怎么帮 |
| --- | --- |
| 不知道这句话怎么回 | 先给一条能直接发送的话，再补时机和后续分支 |
| 想追求、复联、邀约或推进关系 | 给具体行动方案，按照对方反馈继续调整 |
| 看不懂对方，或在多人之间犹豫 | 结合行为、MBTI、主观评分和现实条件给明确判断 |
| 聊天太长、截图太多 | 锁定双方说话人，区分事实、推测和未知；也可分析ChatLab已有数据 |
| **希望以后不用重复交代背景** | **长期记忆**：首次明确同意后，跨任务记住双方档案和关键进展；自动更新、按需召回，随时可以查看、暂停、撤销或清空 |
| 遇到冷淡、冲突、投入失衡、分手或婚姻选择 | 接住情绪，分析利弊，给下一步、观察窗口和停止条件 |

## 不预设你应该爱谁

狗头军师支持异性恋、男同性恋、女同性恋、双性恋、泛性恋、无性恋等不同性取向，也尊重跨性别、非二元性别及其他性别身份。它同样可以讨论单身约会、长期伴侣、婚姻、异地、再婚、跨文化关系，以及建立在知情同意基础上的非单偶关系。

系统不假设固定的性别角色：男女和多元性别用户都可以主动，任何人也都可以选择高主动模式。对于中国常见的男女性约会语境，系统可能在没有明确拒绝或不适时建议男性把主动度提高一级，但这只是可被个人偏好和现实反馈覆盖的文化校准，不是“男性必须追、女性只能等”的定律。判断依据始终是具体的人、具体行为、双方意愿和现实条件。

## 安装

核心使用需要支持 Skills 的 AI 助手；运行自检或使用本地记忆需要 **Python 3.9 或更新版本**，项目脚本只使用 Python 标准库。Git 用于克隆与更新。ChatLab 可选。


将仓库克隆到 Codex 的 Skills 目录：

```bash
git clone https://github.com/ytdongfang77/goutoujunshi.git ~/.codex/skills/goutoujunshi
```

首次安装后，在宿主的技能列表中确认 `goutoujunshi` 已被识别；必要时重新打开任务。若目录已存在，先保留个人修改，再在该目录运行 `git pull --ff-only` 更新。

在 Codex 中输入：

```text
使用 $goutoujunshi 帮我梳理情绪、分析当前关系，并给出下一步建议。
```

首次使用时，它会询问：

```text
你：MBTI / 综合评分0–100 / 主要优势和短板
对象A：代号 / MBTI / 综合评分0–100 / 当前关系
对象B（如有）：同上
经过：认识方式、发展时间、关键事件、联系和投入情况
目标：推进、确认、修复、比较选择，还是退出
情绪：目前最难受的点、强度0–10，以及是否有必须马上回复的消息
```

不知道的项目可以留空，也可以直接讲故事。Skill会从叙述中整理档案，并只追问真正会改变建议的信息。需要跨任务复用时，Skill会单独询问一次是否允许在本机保存精简档案；拒绝不影响正常使用。

### 分析已导出的聊天文件

ChatLab是可选依赖。安装并准备好用户自己取得的聊天导出文件后，可以直接说：

```text
使用 $goutoujunshi 通过 ChatLab 分析我和对象A最近三个月的聊天。
```

狗头军师会先预览导入计划，再限定会话、对象和时间范围查询。它不会直接读取、解密或导出聊天软件数据库；没有ChatLab时仍可粘贴文字或上传截图分析。

## 直接试用

**一句话怎么回**

```text
使用 $goutoujunshi。我们认识一周，对方说“这周有点忙，下周再约吧”。
我想继续了解，先给一句自然回复，再说积极、含糊和不回应时分别怎么办。
```

**按组织局方法复盘**

```text
使用 $goutoujunshi，按组织局 OFDSP 方法分析以下聊天。
先确认谁说了什么，再判断聊天方向、双方投入和下一步。
别替对方读心，也不要为了填模板编造背景。
下面是我的原话和对方的原话：……
```

**改善表达和投入失衡**

```text
使用 $goutoujunshi，结合组织局的能量平衡和短句表达方法，
帮我看看是不是一直在单方面找话题。把我的回复改成平时说话的口气，
说明什么时候该继续、什么时候该停。最近的对话是：……
```

仅讨论案例不会自动启用长期记忆，也不会替用户给任何人发消息。

## 一个典型回答如何产生

```text
用户叙述
  → 情绪落地
  → 建立本人及目标对象档案
  → 分离事实／推测／未知
  → 检索当前情境所需知识
  → 比较互惠、现实、风险与机会成本
  → 给出明确首选建议和理由
  → 生成行动、话术、观察窗口与停止条件
```

长期记忆和ChatLab只在用户同意或提供相应资料时按需使用，不改变这条核心分析流程。

## 运行测试

在克隆后的仓库目录执行：

```bash
python3 scripts/validate_skill.py
python3 scripts/test_skill.py
```

第一条检查 Skill 格式、入口长度、必需资料和本地链接。第二条检查 8 份文件的字节数与 SHA-256、资料能否从 Skill 入口到达、精简安装是否完整，并实际执行记忆脚本的授权、写入、召回、对象隔离、暂停、撤销和删除流程。记忆测试只使用自动清理的临时目录与虚构测试数据。

这些自动测试证明文件完整性和辅助脚本行为；Markdown Skill 的回答质量还需在 AI 助手中做场景试用。不能将结构测试通过解释为模型一定正确判断关系或保证恋爱结果。可复用场景见 [行为验收场景](documentation/behavioral-smoke.md)。

## 设计原则

1. **先接住人，再解决事。** 情绪没有被看见时，最正确的建议也可能无法执行。
2. **行为比标签可靠。** 不凭MBTI、性别或一次聊天记录替目标对象读心。
3. **互惠比追到更重要。** 得到某一个人不是唯一胜利；减少内耗、保留尊严与未来选择权同样是成功。
4. **策略必须说明代价。** 可以讨论撒娇、推拉、节奏和表达包装，但同时交代适用条件与长期成本。
5. **同意和退出权不可绕过。** 明确拒绝不是需要破解的障碍。
6. **危险情境先保安全。** 暴力、胁迫、跟踪、诈骗和自伤风险不能用普通恋爱话术处理。
